# Home Control

SwitchBotスマート電球の共通操作サービス。Stream Deck専用プラグインと将来の専用アプリが同じAPIを利用します。実行時の追加パッケージは不要です。プラグイン登録時には開発用のElgato公式CLIを使います。

GitHubから取得した場合は、先に [Node.js](https://nodejs.org/) 24以降をインストールしてください。このPCでは `runtime/` に配置したNode.jsを使用します。`runtime/`、認証設定の `data/`、生成した `buttons/` はGitの管理対象外です。

## Stream Deck専用プラグイン（推奨）

Windows 10以降、Stream Deck 7.6以降、Node.js 24以降を使用します。

1. 初回は下記のWeb設定画面でSwitchBotの認証情報を保存します。すでに保存済みなら再入力は不要です。
2. プロジェクト内で `npm ci` を実行し、登録用の公式CLIを準備します。
3. `install-plugin.cmd` を実行します。プロジェクト内のプラグインをStream DeckのPluginsフォルダへジャンクションで登録します。
4. 初回登録後はStream Deckを通知領域から終了し、再起動してください。開発者モードが無効だとCLIのrestartは成功表示でも再読み込みされない場合があります。
5. アクション一覧で「Home Control」を検索し、「電球を操作」を空きボタンにドラッグします。
6. 電球を選択し、オン・オフ・切り替え・明るさ・色温度・色を選びます。複数の電球を選ぶと一括操作になります。

プラグインがHome Controlを非表示で自動起動するため、通常は `start.cmd` のウィンドウを開いておく必要はありません。すでに手動起動しているサービスは再利用します。プラグインの終了処理では、自分で起動したサービスだけを停止対象にします。

ボタンのアイコンは黄＝1台以上が点灯、灰＝全台消灯、青＝状態不明です。明るさの値は判定に使わないため、1%でも点灯なら黄色です。電源状態が混在するグループも1台以上点灯していれば黄色になります。操作受付時に予定の色を表示し、1.5秒後・さらに3秒後・さらに5秒後と最大3回状態を確認します。反映待ち中は予定の色を保ち、最終的な不一致・取得失敗の場合は警告します。状態を取得できない場合だけ青へ戻します。ダイヤルが取得した状態もボタンに共有します。常時監視や操作の自動再送はしません。

確認の待機時間は共有キューの外に置き、他の操作を妨げません。確認中に新しい操作を行った場合は、その電球の古い確認処理を無効化し、古い応答で色を上書きしないようにします。

専用プラグインのボタン操作は、同じ電球を選んでいるダイヤルにも同期します。オフ受付時は0%を予想表示し、オン時は既知の明るさまたは自動取得した値を表示します。切り替えも追従し、クラウドの反映待ちはダイヤル押し込みと同じ最大3回の確認を行います。別の電球を操作するボタンではダイヤルを変更しません。複数台ダイヤルの一部だけをオフにした場合や一部失敗では、全台オフの0%を誤表示せず、取得後に混在を表示します。従来の.cmd方式や外部アプリの操作はこの通知の対象外なので、タップで確認してください。

登録先はプロジェクトへのリンクです。このフォルダを移動・削除するとプラグインが動かなくなるため、移動時は登録先と `connection.json` を確認してください。このファイルはインストーラが生成し、Gitの管理対象外です。

### ダイヤルで明るさを調整（Stream Deck +）

1. 更新後にStream Deckアプリを再起動します。
2. アクション一覧の「Home Control → 明るさを調整」をダイヤルの空き枠へドラッグします。
3. 操作する電球を選び、1目盛りの変更幅を設定します。初期値は5ポイント、設定範囲は1〜25ポイントです。
4. 右へ回すと明るく、左へ回すと暗くなります。初回の回転時に現在の明るさを取得します。取得できなければ操作を送信しません。

明るさの範囲は1〜100%です。複数台の場合は選択順の先頭の電球を基準にし、同じ明るさへそろえます。回転を止めて約0.4秒後に最後の値をまとめて送信し、前の通信が続いている場合はその完了後に送信します。送信開始の間隔は最低1秒です。送信中に回した場合も最新値を残し、並行送信しません。

タッチ画面にはパーセントとバーを表示します。電源状態を含む情報を取得した場合は、点灯＝1〜100%、消灯＝0%と表示します。消灯中のAPIに残っている明るさ設定は点灯時の設定として保持し、表示0%と区別します。電源のオン・オフが混在する複数台は--%と表示します。タッチ画面をタップするか、設定画面の「状態を確認」を押すと、現在の状態を読み直します。

上段はSwitchBotに登録した機器名、中央はパーセントとバー、下段は確認中・確認済み・警告などの状態を表示します。複数台は「電球1 ほか3台」のように表示します。機器名は起動時と約60秒ごとに自動更新し、設定画面の「一覧を更新」でも取得できます。SwitchBot側のクラウドに改名が反映されてから、次の取得でダイヤルと開いている設定画面の一覧へ反映されます。画面の開き直しや電球の選び直しは不要です。

機器一覧の取得はプラグイン全体で共有し、同時要求は1回にまとめます。定期取得ではHome Control側のキャッシュも回避します。取得に失敗したときは最後に取得できた名前を残し、次の周期に再試行します。名前の更新では選択ID・明るさ・操作中の状態を変更せず、確認済みの0%も維持します。手入力したボタンのタイトルは自動変更の対象ではありません。

ダイヤルの配置は `streamdeck/com.koroaisu.homecontrol.sdPlugin/brightness-layout.json` で編集できます。アイコンの `rect` は左位置・上位置・幅・高さの順です。点灯・消灯画像は `images/dial-on.svg` と `images/dial-off.svg` を使い、ボタン用とは分けて図形を中央に配置しています。

更新したコードは起動済みのプラグインには自動反映されません。ウィンドウの×で隠すだけでなく、Windowsの通知領域にあるStream Deckアイコンから終了し、起動し直してください。

「押し込み時の動作」で、ダイヤルを押したときの動作を選べます。

- オン／オフ切り替え：選択した各電球の状態を反転します。
- オン／オフ：選択した全台を指定した状態にします。
- 何もしない：押し込みでは操作しません。未設定時の初期値です。以前の「状態を再取得」設定もこの動作として扱います。

押し込みでの「状態を再取得」は廃止しました。画面のタップと設定画面の「状態を確認」は引き続き利用できます。

電源操作は現在の電源状態・明るさを取得してから送信します。取得できなければ予想で電源操作を送信しません。操作時は予想の状態を「変更予定」として表示し、コマンド受付から1.5秒後に自動で状態を再取得します。一致すれば「状態を確認済み」にします。不一致や取得失敗でもすぐ警告せず、予想の表示を保ち、3秒後、さらに5秒後と最大3回確認します。通信時間を除く待機の合計は9.5秒です。

3回確認しても不一致なら、最後に取得した値と「警告：状態が不一致」・警告アイコンを表示します。3回目も取得できなければ--%と警告を表示します。点灯時は電源状態と明るさ、消灯時は電源状態を照合します。クラウド反映の遅れや外部操作の可能性があるため、警告時はタップで再確認してください。読み取りは再試行しますが、操作コマンドは自動再送しません。

自動確認を待っている間も画面のタップで即時確認でき、その場合は予約した取得を取り消して重複通信を防ぎます。電源操作と自動確認が完了するまで、押し込みの連打と回転は受け付けません。未送信の明るさ変更は電源操作を押した時点で取り消し、送信中の通信は完了を待ちます。設定変更・ページ非表示・プラグイン終了では自動確認の予約を取り消し、古い結果で表示を更新しません。

対象を変えたり別のページに移った場合、未送信の変更は取り消します。すでに送信した操作は取り消せません。通信失敗や部分失敗時は待機中の変更も破棄し、自動再送しません。状態を確認してから操作し直してください。

## Web設定画面・従来のファイル方式

1. `start.cmd` をダブルクリックし、ウィンドウを開いたままにします。
2. ブラウザで http://127.0.0.1:3210 を開きます。初回に表示が間に合わなければ再読み込みしてください。
3. SwitchBotのトークン・シークレットを設定画面に入力し保存します。
4. 電球を選んで実行します。機器ごとのボタンは1台、一括ボタンは4台を選びます。
5. 操作を選び「Stream Deck用ファイルを作る」を押し、表示された .cmd をStream Deckの「システム → 開く」に指定します。

API Ninjaは不要になります。従来の生成ファイル方式も引き続き使えます。ボタン生成後にこのフォルダを移動するとパスが変わるため再生成してください。

認証情報は `data/config.json` に平文でローカル保存します。このフォルダを共有・公開しないでください。認証情報をチャットに貼る必要はありません。現在は同一PC内での利用専用で、他のディスプレイ端末からは接続できません。

## 専用アプリ用API v1

同一PCのネイティブアプリは `data/config.json` の apiKey を読み取り、`Authorization: Bearer <apiKey>` を付けます。ブラウザ画面は同一オリジンで提供してください。

- `GET /api/v1/devices` → `{devices:[{provider,id,name,kind,capabilities}]}`。一覧を60秒キャッシュ。`?refresh=1` で再取得。
- `GET /api/v1/devices/switchbot/{id}/status` → SwitchBotから取得した状態。自動ポーリングは行いません。
- `POST /api/v1/actions` → 下記ボディ。`results` は機器ごとの受付結果。部分失敗でも各結果を確認してください。

```json
{"targets":[{"provider":"switchbot","id":"機器ID"}],"action":"on"}
```

action: `on`, `off`, `toggle`, `brightness`（value: 整数1〜100）, `temperature`（value: 整数2700〜6500）, `color`（value: [R,G,B]、各0〜255）。対象は明示指定、最大32台。一括操作は順番に送信するため完全同時ではありません。toggleは各電球の状態を反転します。通信失敗は再送せず、受付成功は実機反映の保証とは区別します。

## 拡張方針

`switchbot.mjs` は接続処理、`server.mjs` は共通HTTP API、`index.html` は設定・操作画面、`client.mjs` はStream Deckからの呼び出しを担当します。接続処理は `devices`, `execute`, `status` を持ち、機器は provider/kind/capabilities で表現します。

現在の実装は電球のみです。エアコン・掃除機を追加する際は機種別capabilitiesと操作の検証を追加します。Alexaの音楽や音量は別providerとして、使用する端末・音楽サービス・認証方式が決まった段階で実装します。外部端末対応時は認証情報の配布・TLS・接続許可を別途設計し、単純に待ち受けアドレスを変えないでください。
